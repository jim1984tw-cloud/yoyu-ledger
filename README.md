# 日常有餘 · GitHub Pages＋Supabase

保留現有記帳、行動支付、先買後付／分期、預算、報表、免費方案候選 AI 切換、離線 PWA 與加密備份。新增 Supabase OAuth 登入、帳號分開的離線帳本與本機版本、跨裝置快照同步，以及發票紀錄管理。

## 本次交付狀態（v3）

程式、資料表 migration、部署流程及測試已備妥。尚未建立 GitHub 儲存庫、啟用 GitHub Pages 或連接實際 Supabase 專案；不能將本機預覽視為雲端已上線。原 Sites 網站沒有被刪除或替換。

## 一次性部署

1. 在 GitHub 建立 **Public** 儲存庫，例如 `yoyu-ledger`，以 `main` 為預設分支。上傳本專案的原始碼、`package-lock.json` 及 `.github/workflows/pages.yml`，不需上傳 `node_modules`。目前沒有授予開源授權；公開可讀不代表允許任意再授權。
2. 到儲存庫 **Settings → Pages → Source** 選擇 **GitHub Actions**。
3. 建立 Supabase **Free** 專案，在 **SQL Editor** 執行 `supabase/migrations/202611050001_ledger_sync.sql`。不需啟用付費方案。表格按 `auth.uid()` 分隔帳目；訪客沒有讀寫權限。
4. 在 Supabase **Authentication → Providers** 啟用 GitHub 登入。建立 GitHub OAuth App，其 callback 為 Supabase 提供的 `https://你的專案.supabase.co/auth/v1/callback`；Client Secret **只填在 Supabase 後台**，不放 GitHub 原始碼或前端。也可改成 Google，需在下列變數選 `google`。
5. 在 Supabase **Authentication → URL Configuration** 設定正式 Pages 網址為 Site URL 與允許的 Redirect URL，例如 `https://你的帳號.github.io/yoyu-ledger/`，保留結尾斜線。
6. 在 GitHub **Settings → Secrets and variables → Actions → Variables** 建立：

   | 變數 | 內容 |
   | --- | --- |
   | `SUPABASE_URL` | 專案 `https://…supabase.co` 網址 |
   | `SUPABASE_PUBLISHABLE_KEY` | `sb_publishable_…`；亦接受舊版 `anon` key |
   | `SUPABASE_AUTH_PROVIDER` | `github`（預設）或 `google` |

   這些是公開連線資訊，不是管理金鑰。**禁止填入 `sb_secret_…` 或 `service_role`**。程式建置時會拒絕這兩種管理金鑰。
7. 在 **Actions → Test and deploy GitHub Pages → Run workflow** 執行部署。等待兩個工作成功，再開啟 Pages 回報的實際網址。尚未填變數時，網站仍可部署為訪客本機模式，但登入與雲端同步尚未可用。

## 舊網站資料搬家

舊 Sites 與 GitHub Pages 是不同來源，瀏覽器資料不會自動跟著移動。

1. 在舊網站「設定」下載完整 JSON 備份，或使用加密備份。
2. 在新網站「設定 → 雲端同步」登入自己的帳號。
3. 使用「還原備份」或「還原加密備份」匯入，核對筆數、帳戶餘額、分期方案與預算。
4. 按「立即同步」，確認顯示成功，再以第二個裝置登入核對。至少保留一份原始備份。

新網站訪客模式已有紀錄時，登入後可按「匯入此裝置的訪客帳本」。此動作會先下載帳號帳本備份；不會把不同帳號資料自行合併。

## 同步行為

- 記帳先寫入本機，約 1.2 秒後嘗試同步。頁面可見時約每分鐘查一次，也會在恢復連線或切回網頁時同步；關閉網頁後不會繼續同步。
- 每個登入帳號各有一份快照與修訂編號。只有預期修訂仍一致時才能寫入，避免舊裝置直接覆蓋新版本。
- 雙方都修改時暫停同步，由使用者選擇整份本機或雲端版本；被取代的資料會觸發 JSON 備份下載。瀏覽器下載成功與否無法由網頁完全確認，請保留檔案。
- 不自動拼接交易與分期關聯，避免重複還款或帳目與排程失配。可從備份手動補回另一份獨有的紀錄。
- 登出切回訪客帳本。帳號本機副本與歷史版本按帳號隔開，但仍留在同一瀏覽器；這是應用層的分隔，不能防止同一裝置管理者讀取儲存空間。
- Supabase 資料依登入與 RLS 限制存取，**不是端對端加密**；加密下載備份功能另行保留。AI Key 不會加入同步內容。

## 免費條件與限制

- GitHub Pages 免費方案使用公開儲存庫；只放程式，不放真實帳目或管理金鑰。GitHub Pages 不適用於商業 SaaS 或處理密碼／完整信用卡號等敏感交易，本專案將 OAuth 密碼輸入留在外部登入頁。
- Supabase Free 受官方資料庫、傳輸與其他配額限制；約一週低活動可能暫停，需後台恢復。沒有永久免費或不中斷保證。
- Gemini 使用自己的未啟用付費帳單專案；可用模型、免費配額與資料政策依 Google 官方。清單不提供帳號是否啟用計費的資訊，不能保證每支 Key 都免費。
- 第三方免費方案變動、API 不可用或超額時，仍可本機記帳與下載備份。不會由本程式自動升級付費方案。

## 開發與驗證

```sh
npm ci
npm test
npm run build
```

建置會把 Supabase SDK 打包至 `dist/vendor/`，無需依賴外部 CDN 來載入登入程式；實際登入、同步與 AI 仍需要網路。供應商程式的授權聲明由打包器保留在產物中。

測試包含既有記帳／分期／AI／備份規則、新增同步衝突／離線失敗／併發修訂／帳號切換保護，以及使用 PostgreSQL 相容引擎執行 SQL migration 和驗證 RLS。

## 發票紀錄（v3）

已加入手動建立、編輯、刪除、月份篩選、搜尋、CSV 範本／預覽匯入／匯出、報帳進度與對應支出連結。同一期同號碼重複會拒絕；匯入 CSV 會預覽錯誤與重複資料，尚有錯誤時不允許送出。

新增發票不會自動入帳；確認新增一筆支出或連結既有相同金額支出後，才建立關聯。發票可以存在於完整 JSON／加密備份與同步快照中。刪除或作廢發票不自動刪除支出，避免變更既有帳務；已刪除支出的關聯會明示需要核對。

目前沒有財政部 API 憑證與安全後端，**尚未串接載具自動下載、官方明細查詢或自動對獎**。來源標記不代表官方驗證。CSV 使用本站提供的欄位格式，並非保證直接接受所有其他發票 App 的匯出檔。v3 已加入照片 QR Code 本機讀取與可選 Gemini 發票辨識，照片只供本次使用，不保存影像。

財政部官方 API 規格要求先申請核准 AppID／APIKey；載具查詢另需載具驗證資料。正式串接應先完成官方申請、授權與安全後端，APIKey／載具驗證碼不可放入 GitHub Pages 原始碼、帳本同步內容或公開儲存庫。

## v3 新功能與使用方式

### AI Key 記住此裝置

在「設定 → AI 小幫手」輸入一次自己的 Gemini Key，勾選「記住在此裝置」，並啟用。下次重開同一網址、同一瀏覽器與帳號會自動載入金鑰並讀取模型清單；離線時保留金鑰於記憶體，網路恢復後辨識會重新讀取清單。可隨時取消記住，或按「清除金鑰」刪除裝置副本。

金鑰以 AES-GCM 密文與不可匯出的 CryptoKey 保存在此瀏覽器的 IndexedDB。這避免把明文寫入一般帳本／匯出檔；**不是防範惡意同來源程式的保險箱**，同來源腳本仍可使用解密金鑰。因此只在自己的裝置啟用，並使用信任的程式來源。金鑰不寫進 GitHub、完整 JSON／CSV、加密備份或 Supabase 帳本快照。

此功能需要瀏覽器提供 IndexedDB 與 Web Crypto，正式 GitHub Pages 的 HTTPS 網址適用；不支援的連線會停用「記住」選項，仍可僅本次使用。新網址、不同瀏覽器／帳號或清除網站資料後，需要重新設定一次。瀏覽器可能清除網站資料，不能保證永不遺失。

### 發票掃描與 AI 照片辨識

1. 「發票紀錄 → 掃描／拍發票」選擇照片，或在手機拍一張發票。
2. 程式先在裝置上讀取 QR Code，支援台灣國內營業人的左側二維條碼：民國日期、含稅總額與賣方統編。店家名稱若未包含，需自行補上。境外電商的外幣／小數擴充格式不自動推測，請手動核對。
3. QR Code 讀不到時，可主動按「AI 辨識這張圖片（傳送 Google）」。僅這張照片會傳送；模型沿用動態清單、免費方案候選與額度不足自動切換。沒有看清楚的金額維持空白，不猜測入帳。
4. 確認後儲存發票，不會自動新增支出。掃碼／AI 結果都不代表財政部驗證真偽，亦不等於取得雲端專屬獎資格。

### 付款配對助手

「發票紀錄 → 付款配對助手」會依相同金額、前後7天與店家名稱列出候選支出。提示只是規則排序，並非機率或官方查核。逐張按「確認連結」後使用既有支出，不重複新增；已被另一張發票連結的交易會排除。也可手動找其他日期的同額支出。

### 代墊與分帳

可建立多人平均或自訂金額分攤，精確到分；自己負擔＋他人分攤需等於實付總額。支援現金、銀行、信用卡、行動支付與先買後付作為付款來源。

代墊部分轉入「應收代墊款」資產，自己的部分才列支出。對方部分還款可分次記錄，收回時從應收款轉至實際收款帳戶，不列收入。還款不得超過該人尚欠金額，支援撤銷誤記收款。這些動作只更新帳目，不會操作銀行或發送催款訊息。

若原付款已記成一般支出，可選擇同日期、同金額、同帳戶且未關聯發票／其他方案的既有支出拆分，避免重複扣款。撤銷此分帳時恢復原支出；已有收款則先撤銷收款。分帳關聯交易不能在普通交易頁直接編輯刪除，請從代墊頁操作。

### 可花金額

計算：目前流動資金 − 未來30天已知的淨流出項目 − 自訂保留金。流動資金只含現金、銀行與獨立錢包，不含信用額度、應收代墊款；內部轉帳不重複扣減。尚未收到的薪資、退款或代墊還款不預先加進來。

會提示信用卡／先買後付待還款尚未完全涵蓋於近期排程的帳戶。仍需補齊排程並對帳；未知日常開銷、稅費或漏記帳款不在估算內，此數字不是保證可花額度。不同帳本共用現金帳戶，所以此估算使用所有帳本資料。
